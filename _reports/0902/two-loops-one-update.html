Two Loops and One Update

The control and data flow of a complete RL training run, in one file. Four levels of nesting, two nested loops, one optimizer step per problem.

5 functions do the learning 2 model calls per rollout 1 tensor carries the gradient V = 151,936 vocab

Control flow

Everything below __main__ is four calls deep. The outer loop walks training steps; the inner loop walks rollouts of a single problem. One optimizer step happens per outer iteration — the inner loop only gathers material for it.

Data flow — one rollout

The model is called twice per rollout, and this is the part worth memorizing: once incrementally with a KV cache to generate tokens, then once on the full sequence to score them. The first call is wrapped in @torch.no_grad(); the second is not. Generation is throwaway; scoring is what learns.

The gradient ledger

Only one thing in the entire step is differentiable. Everything else is bookkeeping around it.

TensorShapeGradWhy
logps[N]YESStacked per-rollout log-probs — the only path from loss to weights
rewards[N]noBuilt from Python floats via grade_answer; never touched the graph
advantages[N]noDerived from rewards, then explicitly .detach()ed in the loss
entropies[N]noCollected with .item() — a metric, never part of the objective
pg_lossscalarYESWhat .backward() is called on
 
# :220-243 — the entire learning rule
rewards    = torch.tensor(roll_rewards, device=device)
advantages = (rewards - rewards.mean()) / (rewards.std() + 1e-4)
logps      = torch.stack(roll_logps)              # [N], the only grad path
pg_loss    = -(advantages.detach() * logps).mean()

Advantages are group-relative: a rollout is scored against its N peers on the same problem, not against an absolute target. That is the "GR" in GRPO, and it removes the need for a value network. It also means a group where every rollout scores identically produces all-zero advantages and contributes no gradient.

What the outer loop does besides training

Every step

append_step_metrics writes one CSV row and mirrors the same numbers to W&B. Also prints a one-line status to stdout.

Every 10 steps

append_sample_logs dumps 3 rollout texts with their rewards and lengths to outputs.txt, and to a W&B table.

Every checkpoint_every

save_checkpoint writes a .pth; if --eval_on_checkpoint is set, runs MATH-500 and records accuracy.

On Ctrl-C

The loop catches KeyboardInterrupt, saves a checkpoint tagged interrupt, and returns the model rather than losing the run.

Why one file is enough

  • No environment. The "env" is extract_final_candidate plus grade_answer — nine lines. Everything that normally makes RL code sprawl is a string comparison here.
  • No value network, no replay buffer, no target network. Group-relative advantages replace the critic; every rollout is consumed by the step that generated it and then discarded.
  • The infrastructure is imported. Transformer, tokenizer, dataset loader and MATH-500 grader all come from reasoning_from_scratch. Only the algorithm is written out — which is what makes the diff between submit_02 and submit_03 readable as exactly one section's contribution.
