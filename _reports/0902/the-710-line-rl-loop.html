01 — THE PREMISEWhy it fits in one file

The reason a single file can run reinforcement learning end to end is that the RL part is small. GRPO on verifiable rewards has no replay buffer, no separate value network, no target network, no environment simulator. It is a sampling loop, a comparison, and one backward pass.

What normally makes RL code sprawl — the environment — is here just a string comparison against a known answer. And what would make this file sprawl is deliberately kept outside it: the transformer, the tokenizer, the dataset loader, and the evaluation harness all come from the installed reasoning_from_scratch package. The file contains the algorithm and nothing else.

02 — THE BOUNDARYInline algorithm, imported infrastructure

"Self-contained" here means no sibling script is imported — not that the file has no dependencies. It still needs the package installed, which is exactly why the cluster job begins with pip install -e .. Drop that line and the pod dies at import.

03 — THE MECHANISMWhat one training step does

This is the part worth holding in your head. One step consumes one math problem and produces one gradient update. Everything between is the loop over rollouts.

The learning rule, in two lines

# submit_03_tracking.py:220-243
advantages = (rewards - rewards.mean()) / (rewards.std() + 1e-4)
pg_loss    = -(advantages.detach() * logps).mean()

That is the whole of GRPO at this stage. A rollout that beat its peers gets a positive advantage, so the loss pushes its log-probability up; one that lagged gets pushed down. When all N rollouts score identically the advantages are all zero and the step contributes nothing — which happened on 309 of your 500 steps.

06 — THE EVIDENCEWhat entropy 5.2 actually looks like

The metrics say the policy degraded. The rollout log in outputs.txt says how badly. Both specimens below are the model's own generation on a MATH problem, from the same run, 470 steps apart.

To solve the equation \((x+2)(x-3) = 14\)… Bring all terms to one side to form a quadratic equation: \(x^2 - x - 20 = 0\)… Therefore, the sum of the possible values of \(x\) is: \(\boxed{1}\)

Alright, my dear fellow mathematicians, I have embarked upon a quest to unravel the enigma of whole numbers… tarra delvelldead lentell banimbru offimebol blace isce tlales enseful blaye blandured sire veiceuxtra jugo fart lotho heed dead succede grunda tedule deferpull

Reward moved from 0.70 to 0.16 — a factor of four. The text moved from correct algebra to invented words. Reward alone would have told you the run got worse; it could not have told you the model was destroyed, because a reward floor of zero looks the same whether the model is confidently wrong or emitting noise. Entropy, response length creeping toward the 1024-token cap, and a loss reaching −673 all say the second thing.

This collapse is not a bug in your setup. It is the failure mode the remaining sections exist to prevent, which is why they arrive in the order they do:

Your run drifted without limit because nothing in submit_03 penalizes drift — the loss is -(adv * logp).mean() and nothing more. Section 7.4's clip and 7.5's KL term are precisely the two brakes missing from Plate 3. Running submit_05_kl.py on the same seed and overlaying its entropy curve on this one is the experiment that closes the loop.
